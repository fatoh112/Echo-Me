# Echo Me architecture rules

- Official visual direction: premium semi-realistic, grounded low-fantasy old-world village and social psychological mystery. Use the imported mountain-village environment as the main town. No modern urban props.
- NPC navigation may build a bounded, low-cost waypoint graph from the imported village's collision while an NPC is ACTIVE. This is navigation only; do not generate or alter world art at runtime.
- Player CharacterBody3D remains authoritative. Configurable walk/run, grounded jump, and smooth camera-relative facing live in PlayerController. Imported character models belong under Body/VisualRoot. Animation and camera presentation never own movement or collision.
- Use one player skeleton/mesh and the offline-baked player_locomotion.res AnimationLibrary. FBX inspection/baking lives in tools/, never gameplay. Remove locomotion root translation; jump height comes from physics. Cache animation references, use short transitions, and evaluate the player once per physics tick. Preview-only turns/start-walk must not delay input. TALK is timed, SIT is a player preview until seating is implemented. Crouch changes the player capsule, camera, gait, and speed together.
- NPCVisual exposes optional humanoid/animation hooks; NPCController remains independent of bones and models. Retarget the player's real locomotion clips to NPC skeletons offline in tools/ and ship one shared NPC library. Only ACTIVE NPCs may evaluate animation. Animation FBXs discard embedded textures.
- Preserve NPC IDs, relationships, and memories when retheming. Canonical town locations must accept legacy save aliases. The fixed imported Mountain Village GLB is the main environment; keep the baked Slavic Town scene only as a non-instanced fallback. No runtime file discovery or procedural generation.
- Preserve source UVs/vertex colors and imported PBR maps. Static village meshes use GI_MODE_STATIC and generated UV2, plus editor-baked LightmapGI. The player and moving NPCs remain GI_MODE_DYNAMIC; they cannot be included in town baking. Keep Forward+ as the desktop renderer and preserve the Compatibility renderer override/fallback. Use measured MEDIUM and HIGH quality profiles, one directional shadow, shadowless local lights, ACES, and atmospheric depth within the GTX 1050 Ti frame budget. Bake LightmapGI in the editor, never at runtime. Keep missing animation states inactive until real clips exist.

- Godot 4.7.2 Standard, GDScript only, Forward+ desktop with Compatibility fallback, Windows first.
- "AI should provide the illusion of intelligence. The game engine should do the actual thinking."
- Decisions use discrete Utility AI, structured memory, relationships, personality, needs, schedules, world state, and event history. NPCs perceive PLAYER actions; actual PLAYER/ECHO source is internal debug data.
- Player traits are floats in 0.0–1.0, initially 0.5, learned with small exponential influences. Echo is the inverse plus at most 0.035 deterministic distortion from a saved seed.
- Use one reusable NPCData/NPCController implementation. Keep action and dialogue definitions centralized under data/.
- main.gd orchestrates. Keep decision, relationship, memory, reputation, persistence, neighborhood, and UI responsibilities in their own small systems.
- Persist versioned JSON in user://; tolerate Day 1 fields, preserve a backup before migration, and use atomic writes. Never commit runtime saves.
- Target i7-2600 / GTX 1050 Ti / 16 GB and weaker hardware. Keep the spatial static town under 100 render batches, use normal Godot import LODs, simple box/cylinder collision, no real-time shadows on local lights, no per-frame GI, no blanket triangle collision, and no individually processed decorative scripts. Slow logical ticks; only nearby ACTIVE NPCs may move on a bounded collision-derived waypoint grid configured by structured data. Distant BACKGROUND and irrelevant LOGICAL NPCs do not run movement or animation logic. No procedural world/asset generation.
- Do not add C#, a local/cloud LLM, ML runtime, PyTorch, TensorFlow, Ollama, CUDA dependency, backend, Render, ElevenLabs, voice, heavy SDK, multiplayer, combat, inventory, quests, procedural world/art generation, parkour, stamina, Steam, settings, save slots, or achievements. The bounded NPC waypoint grid is navigation data only.
- Validate using the portable Godot console executable under F:/mehmed fethelier sultani/. Keep automated tests isolated from the player's production save.
- Before major gameplay refactors preserve the working commit. Commit and push only after parser, headless startup, and meaningful simulation tests pass.
